## 5. 走过的 5 个非显然坑

按发现顺序：

### 5.1 ARM64EC 二进制在 x86-64 host 上 import 必崩
`setup.py:_detect_arch()` 在 AMD64 主机上选 `ARM64EC`，那是给 **X Elite 上跑 x64 Python** 的混合 ABI 二进制。在 `windows-latest`（x86-64 硬件）上 `pip install` + `import qai_appbuilder` 立刻 access violation。结论：**windows-x64 job 必须 build-only**，验证留 Stage B 真机。

### 5.2 包元数据缺 `install_requires`
[setup.py](../setup.py) 没声明 `install_requires`，但 `qai_appbuilder/__init__.py` → `onnxwrapper.py` 顶层 `import numpy / import yaml`。任何用户 `pip install qai-appbuilder` 在干净环境必报 `ModuleNotFoundError`。CI 用 `pip install numpy pyyaml` 绕过。**真正修法**：给 setup.py 加 `install_requires=["numpy", "pyyaml"]`。这是 release-blocker。

### 5.3 `windows-latest` runner image 迁移期 VS 检测失败
CMake 报 `could not find any instance of Visual Studio`，但同样 YAML 之前是绿的。原因：`windows-latest` 正从 `windows-2022` 过渡到 `windows-2025`，过渡期 VS COM 注册偶发不稳定。**修法**：钉死 `windows-2022` + 用 `ilammy/msvc-dev-cmd@v1 arch: amd64_arm64` 显式跑 vcvarsall。

### 5.4 v2.38.0 的 Genie zip 缺新符号
用 v2.38.0 的 `Genie.lib` overlay 到 2.47 SDK，链接报 `unresolved external symbol GenieDialog_embeddingTokenQuery (EC Symbol)` —— `pybind/GenieBuilder.cpp` 引用了 2.47 SDK 才有的新 API。**结论**：overlay 版本必须匹配 SDK，不能用旧版"打桩"。

### 5.5 `QNN_SDK_ROOT` 尾斜杠（两处中招）
- [make/Android.mk:14](../make/Android.mk#L14)：`-I ${QNN_SDK_ROOT}include/QNN`（无分隔符）
- [samples/genie/c++/Service/src/GenieAPIService/dependents.cmake:17-18](../samples/genie/c++/Service/src/GenieAPIService/dependents.cmake#L17-L18)：`$ENV{QNN_SDK_ROOT}lib\\${QNN_PLATFORM}`（无分隔符）

BUILD.md 例子 `Set QNN_SDK_ROOT=C:\...\2.42.0.251225\` 末尾的反斜杠就是这个约定。`setup-qnn-sdk` action 用 `pathlib` 导出没尾斜杠 → wheel build OK（pathlib 不在乎），但 Android NDK build + Genie Service CMake **必须**补斜杠才能找到文件。**修法**：每个用字符串拼路径的 job 在用 `QNN_SDK_ROOT` 前自己加尾斜杠。

## 7. Stage B 待办（同事接手）

按优先级：

### 7.1 包元数据补 `install_requires`（**release-blocker**）
[setup.py](../setup.py) 加：
```python
install_requires=["numpy", "pyyaml"],
```
任何 `pip install qai-appbuilder` 用户都受影响，**不只是 CI**。

### 7.2 修两个真 F821 bug
`ruff check script/ samples/python/utils/` 报的 25 个里这两个是真 NameError：
- [samples/python/utils/image_processing.py:205](../samples/python/utils/image_processing.py#L205) — `numpy_image_to_torch` 未定义/未 import
- [script/qai_appbuilder/onnxwrapper.py:681](../script/qai_appbuilder/onnxwrapper.py#L681) — `exp_shape_by_name` 未定义（被 try/except 吞掉，每次返回 None）

修完把 ci.yml 里 `lint` job 的 `continue-on-error: true` 去掉。

### 7.3 多 SDK 矩阵（GenieAPIService + wheel 通用）
**用户要求**：GenieAPIService 同时支持 **2.47 + 2.46** 两个 SDK 版本（2.45/2.38 暂不做，太老）。

实现方式：把 GenieAPIService job 改成 matrix（参考 [ci.yml](../.github/workflows/ci.yml) 里 `build-windows-x64` 的 matrix 写法）：
```yaml
strategy:
  fail-fast: false
  matrix:
    qnn:
      - version: '2.47.0.260601'
        sdk-url: ''
        genie-url: 'https://github.com/qualcomm/qai-appbuilder/releases/download/v2.47.0/QAIRT_v2.47.0.260601.zip'
      - version: '2.46.0.260424'
        sdk-url: 'https://apigwx-aws.qualcomm.com/qsc/public/v1/api/download/software/sdks/Qualcomm_AI_Runtime_Community/All/2.46.0.260424/v2.46.0.260424.zip'
        genie-url: '<需要 qualcomm/qai-appbuilder 上 2.46 release 的 zip URL>'
```

**风险**：当前 `pybind/GenieBuilder.cpp` 引用了新符号（见 §5.4）。如果 2.46 时代的 Genie 缺这些符号，会链接失败。可能需要在 source 里加 `#ifdef QNN_SDK_2_46` 等版本守卫。**先跑跑看再决定**。

### 7.4 Android GenieAPIService build job
按 [samples/genie/c++/docs/BUILD_ANDROID_README.md](../samples/genie/c++/docs/BUILD_ANDROID_README.md) 做。该文档说有现成 `samples/genie/c++/build_android.bat` 一键脚本。挑战：
- 脚本是 Windows `.bat`，依赖 Windows host
- 需要 NDK r26d（已经在 `build-android-arm64v8a` job 里装过）
- 需要 Java 17（脚本说会自动下载，但 CI 中行为待验证）
- 产物是 Android APK（不是简单 .so）

实现路径：新加一个 `build-android-genie-service` job，runner = windows-2022（脚本是 .bat 必须 Windows），步骤大致：
1. checkout + submodule init `samples/genie/c++/External/*`
2. setup-qnn-sdk
3. setup-ndk@v1
4. set ANDROID_NDK_ROOT / QNN_SDK_ROOT
5. `cd samples/genie/c++ && build_android.bat`
6. 上传 APK artifact

读 BUILD_ANDROID_README.md 全文确认需要哪些环境变量。

### 7.5 Linux GenieAPIService build job
按 [samples/genie/c++/docs/BUILD_LINUX.md](../samples/genie/c++/docs/BUILD_LINUX.md) 做。该文档说"环境跟 wheel Linux build 一样"，所以理论上 `ubuntu-22.04-arm` runner 现成可用。

**主障碍**：
- [Service/CMakeLists.txt:13-15](../samples/genie/c++/Service/CMakeLists.txt#L13-L15) 写死：
  ```cmake
  if (NOT ${CMAKE_SYSTEM_NAME} STREQUAL "Windows")
      message(FATAL_ERROR "current os is: ... only windows support")
  endif ()
  ```
- [dependents.cmake:11-13](../samples/genie/c++/Service/src/GenieAPIService/dependents.cmake#L11-L13) 写死：`only support MSVC and ANDROID platform now`

也就是说 **Service 顶层 CMake 自己拒绝 Linux**。BUILD_LINUX.md 可能给了 patch 或单独的入口（同事接手前请先精读这个文档）。如果该文档假设你用一个不同的 CMakeLists 入口（比如 `Service/src/GenieAPIService/CMakeLists.txt` 直接 build 而不走顶层），就照那个入口写 job。

如果 BUILD_LINUX.md 期待你**修源码** —— 那应该作为单独 PR 提给上游，不在 CI 范围内。

### 7.6 release 自动化
tag `v*` 触发把所有 artifact 上传到 GitHub Release：

新加 workflow `.github/workflows/release.yml`：
```yaml
on:
  push:
    tags: ['v*']

jobs:
  release:
    needs: ci   # 复用 ci.yml 的产物
    ...
    - uses: actions/download-artifact@v4
    - uses: softprops/action-gh-release@v2
      with:
        files: |
          dist/*.whl
          ...
```

挑战：跨 workflow 复用 artifact 有点绕。简单做法：直接把 release.yml 复制 ci.yml 的全部 build 步骤，再加 release 上传。

### 8.3 agent 容易忽略的几条硬规则

- **`QNN_SDK_ROOT` 用字符串拼接时必须尾斜杠**（见 §5.5）
- **windows-x64 是 ARM64EC binary，不在 hosted runner 上 smoke test**（见 §5.1）
- **submodule 选择性 init**：除非显式需要 genie/c++/External/*，否则只 init `pybind/pybind11`。recursive 拉 11 个 submodule 含 llama.cpp + MNN 几百 MB
- **Genie overlay 版本必须匹配 SDK**（见 §5.4）
- **`.github/workflows/build-wheel.yml` 不动**（用户明示保留）

- artifact 内容是否符合预期
