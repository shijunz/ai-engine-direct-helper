## 6. 打地鼠 Playbook

按错误关键字索引。**接手前 5 个最常见的坑**：

### 6.1 `Windows fatal exception: access violation` (smoke test)

**原因**：windows-x64 job 产的是 ARM64EC binary（给 X Elite 上跑 x64 Python 用的混合 ABI），在 x86-64 host 上 import 必崩。

**修法**：windows-x64 job **不能**装/import wheel。仅 build + 上传 artifact。真实测试给 windows-11-arm runner（产 native ARM64 wheel）做。当前 ci.yml 已经这么做了。

### 6.2 `ModuleNotFoundError: No module named 'numpy'` / `'yaml'`

**原因**：之前 setup.py 缺 `install_requires`，commit `7a343c5` 已修。如果再撞见，说明 onnxwrapper.py 又加了新的 top-level import。

**修法**：把新 import 加到 setup.py 的 `install_requires` 里。CI smoke test 步骤里 `pip install numpy pyyaml` 那一行也是兜底（即使 setup.py 不再缺，留着也无害）。

### 6.3 `could not find any instance of Visual Studio` (CMake on Windows)

**原因**：`windows-latest` 是别名，在 windows-2022 → windows-2025 迁移期 VS 检测偶发失败。

**修法**：所有 windows job 用 `runs-on: windows-2022`（钉死，不用别名）。 还要加 `ilammy/msvc-dev-cmd@v1` 显式 vcvarsall。当前 ci.yml 已经这么做。

### 6.4 `LNK1181: cannot open input file 'Genie.lib'` / Android `QnnInterface.h not found`

**原因**：上游有些 cmake/Makefile 用**字符串拼接**构造 SDK 路径（`$(QNN_SDK_ROOT)include/QNN`，无分隔符），需要 `QNN_SDK_ROOT` 以分隔符结尾。setup-qnn-sdk action 用 `pathlib` 导出**没尾斜杠**。

**修法**：每个用字符串拼路径的 job 在 Setup QNN SDK 后自己加一步：
```yaml
- name: Append trailing slash to QNN_SDK_ROOT
  shell: pwsh
  run: |
    $root = $env:QNN_SDK_ROOT.TrimEnd('\','/') + '\'
    "QNN_SDK_ROOT=$root" | Out-File -FilePath $env:GITHUB_ENV -Append -Encoding utf8
```
当前 Android job 和 Genie Service 已加。新 job 用这个模式 SDK 字符串拼路径就需要加。

### 6.5 Linux gcc `extra qualification not allowed`

**原因**：源码里 `namespace std { struct std::hash<X> {...}; }` 多余 `std::`。MSVC 接受，gcc 严格拒。

**修法**：删 `std::`（commit `af9d750` 已修一处）。如果未来再撞见，搜 `struct std::` 看有没有别处。

### 6.6 Android `'tchar.h' file not found` (libappbuilder build)

**原因**：上游 `make/Android.mk` 加了 QAIAppSvc executable target 拉 src/SVC/main.cpp，**该文件 Windows-only**（用 `tchar.h`、`#pragma once` 在 .cpp 文件顶部）。

**状态**：CI 里 Android NDK build job 用 `if: false` 禁用，等上游修。**不要改源码**，这是上游 bug，他们的事。

### 6.7 Android Service `C:hostedtoolcache...` 没斜杠

**原因**：Makefile 把 `$(ANDROID_NDK_ROOT)` 传给 `/usr/bin/bash`（Git Bash），bash 把反斜杠当转义符吞掉。

**修法**：patch `build_android.bat` 时**给 NDK_ROOT 用正斜杠**（QNN_SDK_ROOT 保留反斜杠，因为 cmd.exe 和 cmake 需要 Windows-style）。已在 commit `60aaf70` 修复。

### 6.8 Genie Service USE_MNN / USE_GGUF 链接 / 编译错误

**状态**：当前 USE_MNN=OFF, USE_GGUF=OFF。**不要重新打开**直到你想清楚要修哪条链。打开过的尝试链可在 commit 历史 `8deb5a1`/`b752359`/`04b3d72` 等看到，每条都至少要 3-5 次迭代。

**如果非要打开**：
- 必装独立 LLVM (`choco install llvm`)，不要用 VS 自带 ARM64-host clang
- 必用 `clang-cl.exe`（MSVC driver），不用 `clang.exe`（GNU driver）
- 必给 `MSVC_CLANG_COMPILER` env var 让 dependents.cmake 拿
- llama.cpp 的 ExternalProject 用 Ninja generator，不要 VS generator + ClangCL toolset

详见 stash@{0} 里的 USE_GGUF 改进版（未 commit）。

## 8. setup-qnn-sdk composite action 详解

[.github/actions/setup-qnn-sdk/action.yml](../.github/actions/setup-qnn-sdk/action.yml) 是核心可复用模块。

### 8.1 输入

| input | 默认 | 说明 |
|---|---|---|
| `version` | `2.47.0.260601` | SDK 版本，用于缓存 key |
| `url` | `''` | 覆盖 SDK 下载 URL（空则用 softwarecenter 默认 URL） |
| `genie-runtime-url` | `''` | 定制 Genie zip URL（覆盖 SDK 自带 Genie）|
| `genie-runtime-version` | `''` | Genie zip 版本标签（缓存 key 用）|

### 8.2 输出

- `qnn-sdk-root`: SDK 解压后的根路径
- 同时 export 到 `$GITHUB_ENV` 的 `QNN_SDK_ROOT`

### 8.3 内部流程

OS-agnostic 部分用 step output 桥接 Windows (`pwsh`) 和 Linux (`bash`) 两套实现：

```
1. Resolve SDK URL and install dir (OS-specific)
2. Restore QNN SDK from cache (OS-agnostic)
3. Download and extract QNN SDK (OS-specific)  ← 仅 cache miss 时
4. Locate QNN SDK root and export (OS-specific)
   ← 自动探测两种解压结构：<dir>/lib 或 <dir>/qairt/<version>/lib
5. Genie overlay steps (Windows only, if genie-runtime-url != '')
   - Resolve overlay paths
   - Restore overlay from cache
   - Download + extract overlay (cache miss only)
   - Apply overlay (copy Genie.dll/lib over SDK's, optional GenieDialog.h)
```

### 8.4 Genie overlay 工作原理

BUILD.md 要求用定制版 Genie 覆盖 Community SDK 自带的（上游）Genie，因为 `samples/genie/` 用了定制 API。

overlay zip 结构：
```
<root>/arm64x-windows-msvc/Genie.{dll,lib}  → 给 Windows x64 + ARM64EC 进程
<root>/aarch64-windows-msvc/Genie.{dll,lib} → 给 Windows ARM64 进程
```

仅 Windows。Linux/Android 不做 overlay（zip 没那些 .so）。

**注意版本匹配**：v2.38.0 的 Genie zip 缺 2.46/2.47 SDK 新增的 `GenieDialog_embeddingTokenQuery` 等符号，覆盖后链接失败 —— commit `dce8835` 把那条路径关掉了。
